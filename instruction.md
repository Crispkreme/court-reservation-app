# Laravel + Vercel Deployment Guide

## 1. Create the Laravel Application

- [ ] Create a new Laravel application.
- [ ] Set up all required files and configurations for both the frontend and backend.

## 2. Create a GitHub Repository

- [ ] Create a new repository on GitHub.
- [ ] Initialize Git in your Laravel project.
- [ ] Add and commit the project files.
- [ ] Push the code to the GitHub repository.

## 3. Configure Vercel Files

- [ ] Create a `vercel.json` file.
  - See the `vercel.json` file in this repository for the example configuration.
- [ ] Create `api/lambda.php` by copying `public/index.php` to `api/lambda.php`.
  - See the `lambda.php` file in this repository for the example configuration.
- [ ] Create a `.vercelignore` file.
  - See the `.vercelignore` file in this repository for the example configuration.

> **Important:** Make sure all required Vercel files are created correctly and pushed to the GitHub repository before deploying.

## 4. Create a Vercel Account

- [ ] Go to https://vercel.com
- [ ] Create a Vercel account.
- [ ] If you already have an account, log in.

## 5. Create a Vercel Project

- [ ] Create a new project in Vercel.
- [ ] Import your project from GitHub.
- [ ] Select the GitHub repository containing your Laravel application.

### Vercel Configuration

Set the following project configuration:

| Configuration | Value |
|---|---|
| **Application Preset** | `Other` |
| **Root Directory** | `./` |

### Environment Variables - Initial Deployment

Add the following environment variables:

```env
APP_NAME="Test Vercel App"
APP_ENV=production
APP_KEY=your_laravel_app_key
APP_DEBUG=false
APP_URL=http://localhost:8000
```

> **Note:** `APP_URL=http://localhost:8000` is temporary only.
>
> After Vercel generates your deployment domain, you must change `APP_URL` to the actual Vercel deployment URL.

> **Important:** Replace `your_laravel_app_key` with your actual Laravel application key.
>
> You can get your application key using:
>
> ```bash
> php artisan key:generate --show
> ```

## 6. Deploy the Application

- [ ] Review all Vercel configurations.
- [ ] Make sure the required environment variables are configured.
- [ ] Click **Deploy**.
- [ ] Wait for the deployment to finish.

## 7. Check the Generated Vercel Domain

After the deployment is successful:

- [ ] Open your Vercel project.
- [ ] Check the generated Vercel domain.
- [ ] Open the generated domain in your browser.

Example:

```text
https://test-vercel-deployment-azure.vercel.app/
```

> **Note:** The domain above is only an example. Replace it with the actual domain generated by Vercel.

## 8. Update the Vercel Environment Variables

Go back to your Vercel project:

**Project → Settings → Environment Variables**

Update `APP_URL` and add all of the following environment variables:

```env
APP_URL=https://test-vercel-deployment-azure.vercel.app/

APP_CONFIG_CACHE=/tmp/config.php
APP_ROUTES_CACHE=/tmp/routes.php
APP_EVENTS_CACHE=/tmp/events.php
APP_PACKAGES_CACHE=/tmp/packages.php
APP_SERVICES_CACHE=/tmp/services.php

VIEW_COMPILED_PATH=/tmp

LOG_CHANNEL=stderr

SESSION_DRIVER=cookie

ASSET_URL=/

CACHE_DRIVER=array
CACHE_STORE=array
```

> **Important:** Replace:
>
> ```env
> APP_URL=https://test-vercel-deployment-azure.vercel.app/
> ```
>
> with the actual Vercel domain generated for your project.

> **Important:** Do not forget the additional environment variables.
>
> The following variables are required for this deployment configuration:
>
> - `APP_CONFIG_CACHE`
> - `APP_ROUTES_CACHE`
> - `APP_EVENTS_CACHE`
> - `APP_PACKAGES_CACHE`
> - `APP_SERVICES_CACHE`
> - `VIEW_COMPILED_PATH`
> - `LOG_CHANNEL`
> - `SESSION_DRIVER`
> - `ASSET_URL`
> - `CACHE_DRIVER`
> - `CACHE_STORE`

## 9. Complete Environment Variable Configuration

After updating the environment variables, your final configuration should contain:

```env
APP_NAME="Test Vercel App"
APP_ENV=production
APP_KEY=your_laravel_app_key
APP_DEBUG=false
APP_URL=https://test-vercel-deployment-azure.vercel.app/

APP_CONFIG_CACHE=/tmp/config.php
APP_ROUTES_CACHE=/tmp/routes.php
APP_EVENTS_CACHE=/tmp/events.php
APP_PACKAGES_CACHE=/tmp/packages.php
APP_SERVICES_CACHE=/tmp/services.php

VIEW_COMPILED_PATH=/tmp

LOG_CHANNEL=stderr

SESSION_DRIVER=cookie

ASSET_URL=/

CACHE_DRIVER=array
CACHE_STORE=array
```

> **Important:** Make sure every variable listed above is present in the Vercel Environment Variables.

> **Important:** Replace `your_laravel_app_key` with your actual Laravel application key.

> **Important:** Replace `https://test-vercel-deployment-azure.vercel.app/` with your actual Vercel deployment domain.

## 10. Save the Environment Variables

- [ ] Double-check all environment variables.
- [ ] Make sure `APP_KEY` contains the actual Laravel application key.
- [ ] Make sure `APP_URL` contains the actual Vercel deployment URL.
- [ ] Make sure all `/tmp` cache variables are configured.
- [ ] Click **Save**.

## 11. Redeploy the Application

After saving the environment variables:

- [ ] Go to the **Deployments** section.
- [ ] Select the latest deployment.
- [ ] Click **Redeploy**.
- [ ] Wait for the deployment to finish.

> **Important:** You must redeploy after changing environment variables so that the new configuration is applied to the deployment.

## 12. Test the Application

After the redeployment is complete:

- [ ] Open your Vercel deployment URL.
- [ ] Check if the Laravel application loads correctly.
- [ ] Test the frontend.
- [ ] Test the backend.
- [ ] Test authentication/login if your application has authentication.
- [ ] Test database functionality if your application uses a database.
- [ ] Test API endpoints if your application has APIs.
- [ ] Check the Vercel deployment logs if an error occurs.

## 13. Required Project Files

Before deploying, make sure the following files exist:

```text
your-laravel-project/
│
├── api/
│   └── lambda.php
│
├── public/
│   └── index.php
│
├── vercel.json
└── .vercelignore
```

> **Important:** These files must be committed and pushed to GitHub because Vercel deploys the project from the GitHub repository.

## 15. Important Notes

> **Note 1 - `APP_URL`**
>
> The initial `APP_URL` is temporary:
>
> ```env
> APP_URL=http://localhost:8000
> ```
>
> After Vercel generates the deployment domain, update it:
>
> ```env
> APP_URL=https://your-project.vercel.app/
> ```

> **Note 2 - Additional Environment Variables**
>
> Do not forget the additional environment variables:
>
> ```env
> APP_CONFIG_CACHE=/tmp/config.php
> APP_ROUTES_CACHE=/tmp/routes.php
> APP_EVENTS_CACHE=/tmp/events.php
> APP_PACKAGES_CACHE=/tmp/packages.php
> APP_SERVICES_CACHE=/tmp/services.php
> VIEW_COMPILED_PATH=/tmp
> LOG_CHANNEL=stderr
> SESSION_DRIVER=cookie
> ASSET_URL=/
> CACHE_DRIVER=array
> CACHE_STORE=array
> ```

> **Note 3 - `APP_KEY`**
>
> Never commit your actual Laravel `APP_KEY` to GitHub.
>
> Store the real value in the Vercel Environment Variables.

> **Note 4 - `.env`**
>
> Never commit your `.env` file to a public GitHub repository.
>
> Use Vercel Environment Variables for production configuration.

> **Note 5 - Redeployment**
>
> Always redeploy the application after changing the Vercel Environment Variables.

> **Note 6 - Required Files**
>
> Make sure the following files are present in the GitHub repository:
>
> ```text
> vercel.json
> api/lambda.php
> .vercelignore
> ```
>
> Without these files, this deployment configuration may not work correctly.
